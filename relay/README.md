# Мгновенный отклик через вебхук

По умолчанию бот просыпается по расписанию и отвечает с задержкой до получаса.
Этот модуль убирает задержку: Telegram шлёт сообщение в Cloudflare Worker,
тот мгновенно подтверждает получение и запускает workflow. Полный ответ
приходит примерно через минуту — столько GitHub тратит на старт задачи.

Настройка нужна один раз и занимает минут десять. Обычное расписание при этом
остаётся: цены продолжают проверяться по cron, вебхук отвечает за команды.

## 1. Токен GitHub

Откройте https://github.com/settings/personal-access-tokens/new — это
fine-grained токен, у него можно выдать права только на один репозиторий.

* **Repository access** → Only select repositories → ваш репозиторий
* **Permissions** → Repository permissions → **Actions** → Read and write
* Срок действия на ваше усмотрение; после истечения токен придётся обновить

Скопируйте токен — показывается он один раз.

## 2. Придумайте секрет вебхука

Любая строка из латинских букв и цифр, например `f7k2p9x4m1`. Она нужна,
чтобы никто, кроме Telegram, не мог дёргать ваш воркер. Запишите её.

## 3. Cloudflare Worker

Зарегистрируйтесь на https://dash.cloudflare.com (бесплатного тарифа хватает
с огромным запасом: 100 000 запросов в сутки).

1. **Compute (Workers)** → **Create** → **Start from Hello World** → Deploy.
   Имя может быть любым, например `flight-watch-relay`.
2. Откройте созданный воркер → **Edit code**. Удалите весь шаблон и вставьте
   содержимое `worker.js` из этой папки. Нажмите **Deploy**.
3. Вернитесь в воркер → **Settings** → **Variables and Secrets**. Добавьте
   пять переменных. Первые три отметьте как **Secret**, остальные могут быть
   обычными:

| Имя | Значение | Тип |
|---|---|---|
| `GITHUB_TOKEN` | токен из шага 1 | Secret |
| `WEBHOOK_SECRET` | строка из шага 2 | Secret |
| `TELEGRAM_CHAT_ID` | ваш chat_id | Secret |
| `GITHUB_REPO` | `логин/имя-репозитория` | Text |
| `GITHUB_BRANCH` | `main` | Text |

4. Скопируйте адрес воркера, он вида `https://flight-watch-relay.ВАШ-ЛОГИН.workers.dev`

Проверьте: откройте этот адрес в браузере. Должна появиться надпись
«flight-watch relay: работает».

## 4. Подключите вебхук

Откройте в браузере, подставив свои значения:

```
https://api.telegram.org/bot<ТОКЕН_БОТА>/setWebhook?url=<АДРЕС_ВОРКЕРА>&secret_token=<СЕКРЕТ>
```

Ответ `{"ok":true,...}` означает успех.

Готово. Отправьте боту любую команду: подтверждение «⏳ Принял, запускаю…»
придёт мгновенно, а результат — примерно через минуту.

## Как это устроено

Telegram не умеет добавлять к вебхуку заголовок с авторизацией, а GitHub без
него workflow не запустит. Воркер и решает эту задачу: принимает сообщение,
проверяет секрет и chat_id, затем вызывает GitHub API со своим токеном.

Текст команды передаётся в параметрах запуска workflow, а не забирается
опросом. Так сделано потому, что при включённом вебхуке Telegram отключает
метод `getUpdates` — иначе скрипт просто не увидел бы сообщение.

Подтверждение «Принял» отправляется без отдельного запроса: ответ на вебхук
сам по себе может быть вызовом метода Telegram.

## Если что-то не работает

Проверить состояние вебхука:
`https://api.telegram.org/bot<ТОКЕН_БОТА>/getWebhookInfo`

Поле `last_error_message` покажет, что именно не так.

| Симптом | Причина |
|---|---|
| Подтверждение не приходит | вебхук не подключён либо адрес воркера неверный |
| `⚠️ GitHub ответил 401` | токен неверный или истёк |
| `⚠️ GitHub ответил 403` | у токена нет права Actions: Read and write |
| `⚠️ GitHub ответил 404` | неверный `GITHUB_REPO`, либо workflow ещё не в ветке по умолчанию |
| `⚠️ GitHub ответил 422` | неверная ветка в `GITHUB_BRANCH` |
| Подтверждение есть, ответа нет | смотрите лог запуска в Actions |

Логи самого воркера: в Cloudflare откройте воркер → **Logs** → **Begin log stream**.

## Как вернуться к опросу

```
https://api.telegram.org/bot<ТОКЕН_БОТА>/deleteWebhook
```

Скрипт переключится обратно автоматически: если команда не передана
в параметрах запуска, он опрашивает `getUpdates`, как раньше. Ничего
перенастраивать не нужно.
