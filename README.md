# flight-watch

Мониторинг цен на авиабилеты с уведомлениями в Telegram. Работает на GitHub
Actions, свой сервер не нужен. Пороги срабатывания и частоту проверки можно
менять прямо из чата с ботом.

## Управление из Telegram

| Команда | Что делает |
|---|---|
| `/status` | текущие настройки и последние цены |
| `/check` | проверить цены прямо сейчас |
| `/routes` | список отслеживаемых маршрутов |
| `/add AMS SAW 2027-02-14 2027-02-28` | добавить маршрут |
| `/del 2` | удалить маршрут номер 2 |
| `/find амстердам` | найти IATA-код по названию |
| `/drop 7` | уведомлять при падении цены на 7% |
| `/max 350` / `/max off` | абсолютный порог цены |
| `/rise 15` / `/rise off` | предупреждать о росте цены |
| `/freq 180` | проверять цены раз в 180 минут |
| `/pause` / `/resume` | приостановить и возобновить слежение |
| `/source pegasus on` | включить или выключить источник |
| `/help` | справка |

### Маршруты из чата

```
/add AMS SAW 2027-02-14 2027-02-28
```

Аэропорт вылета, аэропорт прилёта, дата туда, дата обратно. Без второй даты
маршрут считается билетом в одну сторону. Вместо даты можно указать месяц
(`2027-02`) — тогда отслеживается вся вилка дат внутри него.

После дат можно дописать в любом порядке:

| Что дописать | Что это значит |
|---|---|
| `PC,VF` | следить только за этими авиакомпаниями |
| `direct` | только прямые рейсы |
| `Стамбул весной` | своё название маршрута для уведомлений |

Например: `/add LED IST 2027-04 2027-05 PC,VF direct Стамбул весной`

Ввод проверяется: код должен существовать в справочнике, дата — быть
корректной и ещё не прошедшей, обратная дата — не раньше даты вылета,
дубликаты не создаются. При ошибке бот объясняет, что не так.

**Коды аэропортов.** Если не знаете код, спросите: `/find стамбул`. Бот
покажет и код города (`IST`), и коды отдельных аэропортов (`SAW`).
Код города обычно даёт больше вариантов, потому что охватывает все аэропорты
сразу. Код конкретного аэропорта нужен, когда вам важен именно он —
например, `SAW` для Pegasus и AJet, у которых там база.

Справочник берётся из открытых файлов Travelpayouts (без токена), при первом
обращении скачивается, обрезается и сохраняется в `airports-db.json`, который
коммитится в репозиторий. Если скачать не удалось, бот продолжает работать,
просто проверяет коды по формату и не подсказывает названия.

Маршруты хранятся в `settings.json` и целиком управляются из чата —
в `config.yaml` их нет. В файле лежат только общие настройки: валюта,
рынок и список источников.

Если какой-то маршрут нужно защитить от удаления из чата, его можно прописать
в `config.yaml` по образцу из комментария в конце файла. В списке `/routes`
такие маршруты помечаются замком: они проверяются наравне со всеми, но `/del`
их не трогает.

**Важное ограничение.** GitHub Actions не может держать бота онлайн постоянно.
Команды забираются пачкой при каждом запуске workflow, так что ответ приходит
не мгновенно, а в течение получаса (по умолчанию workflow запускается каждые
30 минут). Это цена за отсутствие сервера. Если нужна мгновенная реакция —
бота придётся перенести на постоянно работающую машину.

Команды принимаются только от того `chat_id`, который указан в секретах;
сообщения от посторонних игнорируются.

## Источники цен

| Источник | Статус | Что это |
|---|---|---|
| `travelpayouts` | работает сразу | Кэш цен Aviasales. Бесплатный ключ, покрывает все авиакомпании, включая Pegasus (`PC`) и AJet (`VF`). |
| `pegasus` | нужна калибровка | Прямой скрапинг flypgs.com через браузер. |
| `ajet` | нужна калибровка | Прямой скрапинг ajet.com через браузер. |

### Про Pegasus и AJet — прочитайте до включения

Ни у одной из этих авиакомпаний нет публичного API. Скраперы открывают их сайт
в настоящем браузере (Playwright) и перехватывают внутренние JSON-ответы.
Подход рабочий, но с оговорками:

* **Блокировки.** У обеих стоит антибот-защита, и датацентровые IP GitHub
  Actions она режет охотнее всего. Вполне вероятно, что локально скрапер
  заработает, а в Actions будет стабильно получать страницу с капчей.
* **Хрупкость.** URL поиска и формат ответов меняются без предупреждения,
  примерно раз в несколько месяцев потребуется перекалибровка.
* **Время.** Установка браузера добавляет около минуты к каждому запуску.
  Поэтому она выполняется, только если хотя бы один скрапер включён.
* **Условия использования.** Автоматический сбор данных обычно противоречит
  пользовательскому соглашению сайтов. Для личного мониторинга это бытовая
  серая зона, для чего-то большего — уже нет.

**Сначала попробуйте без них.** Aviasales отдаёт цены `PC` и `VF`, и фильтр
`airlines: [PC, VF]` в `config.yaml` закрывает задачу без единого скрапера.
Скраперы имеют смысл, только если вы убедились, что в кэше Aviasales цен
этих перевозчиков по вашему маршруту нет, либо что они систематически выше,
чем на сайте авиакомпании (у лоукостеров так бывает с багажными тарифами).

### Калибровка скрапера

Выполняется один раз на своём компьютере, не в Actions:

```bash
pip install playwright && playwright install chromium
python calibrate.py pegasus
```

Откроется браузер. Сделайте обычный поиск билетов руками и дождитесь списка
рейсов. Утилита запишет все JSON-ответы сайта, определит, в каком из них лежат
цены, и напечатает готовый блок для `config.yaml`. Останется заменить в URL
конкретные города и даты на плейсхолдеры `{origin}`, `{destination}`,
`{departure_date}`, `{return_date}`.

Потом включите источник: `/source pegasus on`.

## Установка

### 1. Токен Travelpayouts

Зарегистрируйтесь на [travelpayouts.com](https://www.travelpayouts.com/) —
это партнёрская программа Aviasales, аккаунт бесплатный. Токен лежит в
профиле: https://app.travelpayouts.com/profile/api-token

### 2. Telegram-бот

1. Напишите [@BotFather](https://t.me/BotFather), отправьте `/newbot`.
   Получите токен вида `123456789:AAE...`.
2. Напишите своему боту любое сообщение — без этого он не сможет вам отвечать.
3. Узнайте свой chat_id: откройте
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates` и найдите `"chat":{"id":...}`.
   Либо спросите у [@userinfobot](https://t.me/userinfobot).

### 3. Репозиторий и секреты

Загрузите содержимое папки в репозиторий на GitHub. В
**Settings → Secrets and variables → Actions** добавьте три секрета:

| Имя | Значение |
|---|---|
| `TRAVELPAYOUTS_TOKEN` | токен из шага 1 |
| `TELEGRAM_BOT_TOKEN` | токен бота |
| `TELEGRAM_CHAT_ID` | ваш chat_id |

### 4. Маршрут

Редактировать `config.yaml` не нужно. После запуска отправьте боту
`/add AMS SAW 2027-02-14 2027-02-28` — маршрут появится сразу. Пороги
и частота тоже настраиваются из чата.

### 5. Проверка

**Actions → flight-price-monitor → Run workflow**, галочка `force`. Если
сообщение пришло — всё работает. Дальше отправьте боту `/status`.

Локально:

```bash
pip install -r requirements.txt
export TRAVELPAYOUTS_TOKEN=... TELEGRAM_BOT_TOKEN=... TELEGRAM_CHAT_ID=...
python monitor.py --dry-run --force
```

## Частота и лимиты Actions

Здесь две разные величины:

* **cron в workflow** — как часто просыпается скрипт. Это потолок частоты
  и заодно задержка реакции на команды бота.
* **`check_interval_minutes`** (команда `/freq`) — как часто он реально
  опрашивает источники. Может быть любым числом, кратным cron или больше него.

Смысл разделения: команды из Telegram нужно забирать часто, а цены дёргать
редко. Ставить `/freq` меньше шага cron бесполезно — бот об этом предупредит.

| cron | Запусков в месяц | Минут Actions |
|---|---|---|
| `7 * * * *` (раз в час) | ~720 | ~720 |
| `7,37 * * * *` (по умолчанию) | ~1440 | ~1440 |
| `*/15 * * * *` | ~2880 | ~2880 |

В **публичном** репозитории Actions бесплатны без лимита. В **приватном** —
2000 минут в месяц на free-плане, и вариант по умолчанию съедает почти всё.
Секретов в коде нет, в `history.json` только цены, так что репозиторий спокойно
можно сделать публичным. Иначе поставьте `7 * * * *`.

GitHub запускает cron с задержкой 5–20 минут и может пропустить запуск при
высокой нагрузке. Скрипт это учитывает: интервал проверяется с допуском.

## Как устроены уведомления

Приходят не на каждую проверку, а когда цена изменилась существенно: упала на
`drop_percent` относительно последнего уведомления, опустилась ниже `max_price`
или выросла на `rise_percent`. Цены всех источников сравниваются между собой,
в сообщение идёт минимальная, остальные показываются строкой «для сравнения».

История хранится в `history.json` и коммитится после каждого запуска — заодно
это не даёт GitHub отключить расписание за неактивность репозитория.
